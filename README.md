# Telegram Habit Tracker

Telegram Habit Tracker --- приложение для отслеживания привычек и
получения напоминаний через Telegram-бота. Проект использует FastAPI для
HTTP API и PostgreSQL для хранения данных.

## Возможности

-   Управление привычками через API.
-   Хранение данных в PostgreSQL.
-   Telegram-бот и отправка напоминаний.
-   Авторизация API с помощью JWT.
-   Миграции базы данных через Alembic.
-   Автоматические тесты с pytest.
-   Запуск сервисов через Docker Compose.

## Технологии

Python 3.11, FastAPI, Uvicorn, PostgreSQL, SQLAlchemy, Alembic, Pydantic
Settings, PyJWT, pyTelegramBotAPI, APScheduler, Poetry, Docker Compose и
pytest.

## Требования

-   Docker Desktop с поддержкой Docker Compose.
-   Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).

## Настройка

1.  Перейдите в каталог проекта.
2.  Создайте файл `.env` на основе `.env.example`:

``` bash
cp .env.example .env
```

3.  Заполните переменные окружения. Сверьте их названия с `.env.example`
    и `docker-compose.yml`. Укажите токен Telegram-бота, секреты
    приложения и пароль базы данных.

Не публикуйте файл `.env` и не добавляйте реальные секреты в
репозиторий. Если строка подключения к базе данных использует хост `db`,
оставьте его при запуске через Docker Compose: это имя сервиса
PostgreSQL внутри сети Compose.

## Запуск через Docker Compose

Из каталога, где находится `docker-compose.yml`, выполните:

``` bash
docker compose up --build -d
```

Проверить состояние сервисов:

``` bash
docker compose ps
```

Посмотреть логи всех сервисов:

``` bash
docker compose logs -f
```

Логи отдельного сервиса:

``` bash
docker compose logs -f api
docker compose logs -f bot
docker compose logs -f notifier
```

Остановить сервисы без удаления данных базы:

``` bash
docker compose down
```

**Важно:** не используйте `docker compose down -v`, если хотите
сохранить данные PostgreSQL. Флаг `-v` удаляет связанные тома и может
привести к потере данных.

## Документация API

После запуска API документация Swagger UI обычно доступна по адресу:

-   `http://localhost:8000/docs`
-   OpenAPI-схема: `http://localhost:8000/openapi.json`
-   Проверка состояния: `http://localhost:8000/health`

Если порт или адрес изменены в `docker-compose.yml`, используйте
значения из конфигурации проекта.

## Запуск тестов

Запустите тесты внутри контейнера API:

``` bash
docker compose exec api python -m pytest -v
```

## Безопасность

-   Храните токены и секреты только в `.env` или защищённом хранилище
    секретов.
-   Не публикуйте `.env` и не показывайте действующие токены на
    скриншотах.
-   Используйте уникальные секреты для JWT и внутренних механизмов
    авторизации.
-   Для реального развёртывания настройте HTTPS, ограничьте доступ к
    базе данных и задайте надёжные пароли.

## Часовой пояс напоминаний

Часовой пояс напоминаний должен соответствовать настройкам приложения.
Если в конфигурации используется `Asia/Baku`, настройте его для
планировщика напоминаний; менять системный часовой пояс контейнеров без
необходимости не требуется.

## Зависимости

Проект использует Poetry. Список зависимостей находится в
`pyproject.toml`. Для воспроизводимой установки рекомендуется создать и
сохранить в репозитории `poetry.lock`, проверив его в окружении проекта.
